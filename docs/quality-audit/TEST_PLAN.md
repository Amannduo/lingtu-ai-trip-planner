# 灵途 AI 旅行规划师 — 专业测试方案

> 基于《项目理解报告》定制，非通用模板堆砌。

## 1. 测试范围与优先级

| 测试领域 | 是否适用 | 优先级 | 测试原因 |
| --- | --- | --- | --- |
| 后端单元/集成（现有 pytest） | 是 | P0 | 质量门/语义/鉴权/任务核心回归基线 |
| API 契约与参数校验 | 是 | P0 | FastAPI 入口是主攻击面与业务面 |
| 身份认证与越权 | 是 | P0 | Cookie 会话 + 多角色 + 历史隔离 |
| 行程生成业务规则 | 是 | P0 | 日期/天数/预算/质量门/语义硬拦截 |
| 异步 plan-jobs / SSE / 取消 | 是 | P0 | 状态机复杂，易脏写 |
| 限流与容量 | 是 | P1 | 429 行为与成本控制 |
| 数据库约束与一致性 | 是 | P1 | SQLite 默认 + 迁移完整性 |
| 第三方降级（地图/LLM/邮件/Push） | 是 | P1 | 失败不得破坏已保存行程 |
| 安全（注入/XSS 载荷/路径/上传） | 是 | P0 | 分析 SQL、文件上传、公开 API |
| 前端构建与类型检查 | 是 | P1 | 无前端单测，build 是最低保障 |
| 前端 UX 手工/冒烟 | 是 | P1 | 核心转化路径 |
| 性能与小规模并发 | 部分 | P2 | 正式压测受限；做冒烟并发 + 代码审阅 |
| 真实 e2e（真实 LLM+高德） | 条件性 | P2 | 依赖密钥与费用；有密钥再跑 |
| 移动端专项 | 低 | P3 | Web 响应式，非原生 App |
| 支付 | 否 | — | 无支付模块 |

## 2. 测试计划要素

| 要素 | 内容 |
| --- | --- |
| **测试目标** | 验证核心行程规划链路正确、安全、可恢复；暴露可复现缺陷；评估发布 readiness |
| **测试对象** | backend API/services/agents；frontend build；SQLite schema/migrations；配置与 Docker postgres 定义 |
| **测试环境** | Windows + 本地 Python/Node；SQLite `backend/data` 或临时测试库；不写生产；第三方默认 mock/dry-run |
| **测试数据** | pytest fixture 隔离库；主动 API 探测用一次性用户名；测后清理 |
| **测试方法** | 静态分析 → 环境验证 → 全量 pytest → 主动 HTTP 探测 → 安全用例 → 小并发 → 前端 build → 补充回归测试 |
| **预期结果** | pytest 全绿或可解释失败；关键 API 行为符合规则；发现的 Bug 有复现步骤与根因 |
| **风险和限制** | 无真实高德/LLM 时完整生成 e2e 受限；无浏览器自动化时 UX 以代码+构建为主；进程内限流测不全集群；不攻击外网 |
| **完成标准** | 理解报告+方案+执行记录+Bug 清单+总结报告齐全；关键失败已分类；必要回归测试已补充 |

## 3. 分阶段执行清单

1. 环境与依赖、alembic、health、配置校验
2. `pytest -q` 全量 + compileall + frontend build
3. 主动用例：校验/边界/越权/重复提交/异常降级
4. 数据库约束与迁移
5. 安全非破坏探测
6. 小并发与限流
7. 前端构建与 API 冒烟
8. 缺口补测与最终报告
